# 日志与排查

在新项目目录运行下列命令可查看本地日志位置。

```powershell
.\scripts\run_abo.ps1 -Command logs
```

## 项目级记录

| 文件 | 记录内容 |
| --- | --- |
| `abo_runtime/upstream/VisRAG/personal/a_baseline/docs/操作方法与结果记录.txt` | 会话开始、结束、使用入口、实际结果、产物位置、验收和关联问题。开发、部署、下载等人工操作也在这里补记。 |
| `abo_runtime/upstream/VisRAG/personal/a_baseline/docs/问题与解决记录.txt` | 按问题编号记录现象、原因、解决方法、复验和状态。修复后继续追加同一编号，原错误保留。 |
| `abo_runtime/记录/逐题结果汇总.txt` | 本工作区各入口完成的逐题结果及相应来源。 |

在排查确认原因和复验结果后，可在项目 Python 环境中通过 `app.abo.service.bind_runtime()` 初始化运行目录，调用 `common.update_issue(编号, 原因, 解决方法, 验证结果, 状态)`。实际未知的原因或未跑过的复验按当时状态记录。

## 每次会话

本地运行目录在 `abo_runtime/reports/ecommerce_rag/<会话名>`。PowerShell 结束后会打印对应路径。HTTP 返回 `run_name` 和 `question_id`，异常有相应的 `issue_id`。

| 文件 | 记录内容 |
| --- | --- |
| `对话记录.txt` | 用户问题、实际显示给用户的回复、来源标签、策略和异常编号。同一份文件含普通商品对话与配件兼容对话。 |
| `逐题结果.txt`、`results.jsonl` | 问题 ID、参考答案与证据页、召回页与排名、原始回答结构、可见回答、引用、检索和生成耗时、模型及配置版本。自由提问的参考答案标记为未标注。 |
| `运行记录.txt`、`运行事件.jsonl` | 开始、就绪、异常回退、失败、结束和关联问题。启动失败时可先查看这里。 |
| `config.json`、`source_snapshot/` | 当前运行配置与源码快照。镜像会话保留云端配置、原会话名和原问题号，源码快照留在 Kaggle。 |

GPU 多任务回答额外保存任务计划、各工具结果、需求检查、推荐候选、语义生成和来源复核的原始输出。断线重试记录通道错误与恢复结果；请求编号用于防止重复执行。新对话是独立线程事件，不会伪装成用户输入“重置”。

网页历史和可恢复状态在 `abo_runtime/reports/web-threads/`，Kaggle 侧对应 `web-cloud-threads/` 与 `web-cloud-requests/`。其中保存的商品身份和用户需求用于恢复会话，回答商品事实时仍重新取证。这些本地记录不提交到 GitHub。

在“对话记录”中确认删除一段会话后，本机历史文件只保留编号、删除标记与时间，不再保存该段正文和恢复快照。删除操作记入操作日志；逐题审计目录及云端实验日志独立保留，删除历史不代表清除这些审计资料。删除接口与断开 Kaggle 接口分开，避免删除历史时关闭其他对话共用的模型。

正常的范围提示、缺证据、价格不可查或需要澄清会写进对话与逐题日志。技术异常与异常回退进入问题记录。识别到的凭据和联系方式在落盘时脱敏。ASIN 和站点保留用于证据追踪。

## Kaggle 和 PowerShell 远程入口

- Kaggle 就绪时打印会话目录，通常在 `/kaggle/working/abo-rag/reports/ecommerce_rag`。引导初始化写入 `/kaggle/working/ABO启动记录.txt`。
- 交互结束可调用 `close_chat()` 写结束事件。重新执行初始化单元格可新建会话。逐轮记录在每次回答时落盘，强制停止可能缺少正常结束事件。保存 Notebook 运行后可从该版输出下载日志。
- PowerShell 的 `cloud-chat` 额外镜像已收到的云端逐题行与可见对话至本地。失败的连接或请求也有本地运行记录。连接地址用于建立连接，日志不记录地址输入。
- GitHub 发布源码、可复制的流程和日志说明。各次实际对话、问题与运行记录保存在对应本地工作区与私有 Notebook 输出。
